# Эмулятор оболочки операционной системы (Вариант 23)

## 1. Общее описание
Данное программное обеспечение является консольным эмулятором командной строки UNIX-подобной операционной системы. Приложение функционирует в интерактивном режиме REPL (Read-Evaluate-Print Loop), обеспечивая непрерывный диалог с пользователем. 

Проект разработан на языке программирования Python 3.12 в рамках выполнения лабораторной работы по дисциплине «Конфигурационное управление». Архитектура эмулятора спроектирована с учетом изоляции виртуальной среды от реальных файлов на жестком диске.

## 2. Описание всех функций и настроек

### Параметры командной строки (Этап 2)
Эмулятор является настраиваемым. При запуске поддерживаются следующие параметры:

| Параметр | Описание |
|---|---|
| `--vfs <путь>` | Путь к физическому расположению VFS. Имя файла (без расширения) используется как имя VFS в приглашении к вводу. Если параметр не задан, используется имя `my_virtual_vfs`. |
| `--script <путь>` | Путь к стартовому скрипту с командами эмулятора. |
| `-h`, `--help` | Вывод справки по параметрам. |

При запуске эмулятор выводит отладочную информацию обо всех заданных параметрах (строки с префиксом `[DEBUG]`).

### Стартовый скрипт
Стартовый скрипт — текстовый файл (UTF-8), в каждой строке которого записана одна команда эмулятора. Функция `run_script()` выполняет команды последовательно:
* на экране отображается как ввод (приглашение + команда), так и вывод, имитируя диалог с пользователем;
* пустые строки пропускаются;
* ошибочные строки (неизвестная команда, неверные аргументы) пропускаются с сообщением `Ошибка в стартовом скрипте (строка N): '...' пропущена`, после чего выполнение продолжается;
* если файл скрипта не удалось открыть, выводится сообщение об ошибке;
* команда `exit` в скрипте завершает работу эмулятора.
* после выполнения скрипта выводится итоговое сообщение: `Стартовый скрипт выполнен без ошибок` или `Ошибка: стартовый скрипт выполнен с ошибками (строки: ...)`. Итоговое сообщение выводится и тогда, когда скрипт завершается командой `exit`.

После выполнения скрипта (если он не завершился командой `exit`) эмулятор переходит в интерактивный режим REPL.

### Виртуальная файловая система (Этап 3)
VFS загружается из CSV-файла, указанного в параметре `--vfs`. Все операции производятся в памяти: CSV-файл только читается и никак не изменяется.

**Формат CSV-файла.** Первая строка — заголовок `path,type,content`, далее каждая строка описывает один элемент VFS:

| Столбец | Описание |
|---|---|
| `path` | Полный путь к элементу от корня, начинается с `/`. Вложенность задается через `/`, например `/home/user/docs/file1.txt`. |
| `type` | Тип элемента: `dir` (папка) или `file` (файл). |
| `content` | Содержимое файла в формате base64 (подходит и для текстовых, и для двоичных данных). Для папок и пустых файлов — пустое значение. |

Пример:
```text
path,type,content
/home,dir,
/home/user,dir,
/home/user/hello.txt,file,0J/RgNC40LLQtdGCIQo=
```

Недостающие родительские папки создаются автоматически. В памяти VFS хранится как вложенные словари: папка — словарь `имя -> элемент`, файл — байты (`bytes`).

Если параметр `--vfs` не задан, используется пустая VFS. При ошибке загрузки выводится сообщение `Ошибка загрузки VFS: ...` и эмулятор завершается с кодом `1`. Ошибками считаются:
* файл VFS не найден или не открывается;
* неверный заголовок CSV;
* строка с неверным числом столбцов;
* путь не начинается с `/`;
* неизвестный тип элемента;
* содержимое файла не в формате base64;
* файл используется как папка или путь повторяется.

После загрузки выводится отладочная строка с числом папок и файлов: `[DEBUG] VFS загружена: папок N, файлов M`.

Готовые VFS находятся в папке `vfs/`:
* `minimal.csv` — минимальная VFS (только корень);
* `files.csv` — несколько файлов (текстовые, пустой и двоичный);
* `nested.csv` — 3 и более уровней файлов и папок;
* `bad.csv` — VFS с ошибкой (содержимое не в base64) для проверки обработки ошибок.

### Компоненты эмулятора
* **Интерфейс REPL:** Бесконечный цикл чтения ввода, синтаксического разбора и последовательного вывода результатов обработки. Принимает строки от пользователя через стандартный поток ввода (`input()`).
* **Динамическое приглашение (Prompt):** Согласно требованиям Варианта 23, промпт формируется функцией `get_prompt()` и включает в себя имя виртуальной файловой системы, например `my_virtual_vfs> ` или `nested> ` (при запуске с `--vfs vfs/nested.csv`).
* **Парсер строк с поддержкой окружения:** Функция `parse_input()` выполняет токенизацию введенной строки (разделение по пробелам) и осуществляет автоматическое раскрытие системных переменных окружения реальной операционной системы (например, `$USERNAME`, `$HOME`, `$PATH`) при помощи модуля `os.path.expandvars`.
* **Обработка исключений:** Встроенный блок `try-except` перехватывает сигналы прерывания процесса `KeyboardInterrupt` (сочетание клавиш Ctrl+C) и `EOFError`, выполняя корректный системный выход без вывода аварийного лога (Traceback).

### Поддерживаемые команды:
* `exit` — выполняет штатное завершение работы эмулятора с кодом `0`. Поддерживает валидацию аргументов: при попытке ввода дополнительных параметров выводит сообщение об ошибке `exit: too many arguments`.
* `ls` — команда-заглушка. Принимает любые параметры и флаги, выводит свое имя и переданные аргументы.
* `cd` — команда-заглушка для имитации смены текущего рабочего каталога. Выводит имя команды и список переданных ей аргументов.

## 3. Описание команд для сборки проекта и запуска тестов

### Сборка и зависимости
Проект написан с использованием стандартной библиотеки Python и не требует установки сторонних пакетов (`requirements.txt` отсутствует). Для изоляции рекомендуется использовать стандартное виртуальное окружение:

```bash
python -m venv .venv
```

### Запуск проекта
Запуск эмулятора осуществляется напрямую через интерпретатор:
```bash
python src/emulator.py
```
Также в папке `scripts/` подготовлены автоматизированные скрипты реальной ОС Windows для проверки различных сценариев вызова эмулятора:
* Запуск штатного режима: `.\scripts\run.bat`
* Тестирование вызова справки CLI: `.\scripts\run_help.bat`

Скрипты для тестирования параметров командной строки (каждый вызывает эмулятор с параметрами `--vfs` и `--script`):
* Стартовый скрипт без ошибок (`scripts/start_ok.txt`): `.\scripts\run_script_ok.bat`
* Стартовый скрипт с ошибочными строками (`scripts/start_errors.txt`): `.\scripts\run_script_errors.bat`
* Несуществующий стартовый скрипт: `.\scripts\run_script_missing.bat`

Скрипты для тестирования работы с различными вариантами VFS (все используют стартовый скрипт `scripts/start_vfs.txt`, который проверяет все реализованные команды и обработку ошибок):
* Минимальная VFS: `.\scripts\run_vfs_minimal.bat`
* VFS с несколькими файлами: `.\scripts\run_vfs_files.bat`
* VFS с 3 и более уровнями вложенности: `.\scripts\run_vfs_nested.bat`
* Ошибки загрузки VFS (несуществующий файл и неверные данные): `.\scripts\run_vfs_errors.bat`

Запуск с параметрами вручную:
```bash
python src/emulator.py --vfs vfs/nested.csv --script scripts/start_vfs.txt
```

### Запуск автоматических тестов
Для проведения модульного тестирования используется встроенный фреймворк `unittest`. Запуск всех тестов из папки `tests/`:
```bash
python -m unittest discover -s tests
```

## 4. Примеры использования

### Интерактивный сеанс работы (REPL)
```text
my_virtual_vfs> ls -la /home
[Заглушка] Вызвана команда: ls
Переданные аргументы: -la /home

my_virtual_vfs> cd scripts
[Заглушка] Вызвана команда: cd
Переданные аргументы: scripts
```

### Раскрытие переменных окружения ОС
```text
my_virtual_vfs> ls $USERNAME
[Заглушка] Вызвана команда: ls
Переданные аргументы: Даша
```

### Обработка синтаксических ошибок и неизвестных команд
```text
my_virtual_vfs> clear
clear: command not found

my_virtual_vfs> exit с_аргументами
exit: too many arguments
```
